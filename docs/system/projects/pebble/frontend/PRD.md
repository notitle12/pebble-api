# Pebble 프론트엔드 요구사항

작성일: 2026-10-03. 기존 제품·API 계약을 화면 요구사항으로 옮긴 설계 초안이다. 새로운 제품 정책이나 구현 완료 선언이 아니다.

## 1. 문서의 범위와 기준

사용자 web과 관리자 adminweb은 별도 프론트이며 같은 api를 이용한다. 제품 범위는 [백엔드 PRD](../backend/contracts/PRD.md), HTTP 계약은 [API](../backend/contracts/API.md), 권한은 [SECURITY](../backend/contracts/SECURITY.md)가 기준이다. 이 문서는 화면 목적과 완료 조건을 정한다.

SSR·SPA는 화면을 만드는 방식이다. SSR은 서버가 데이터를 조회해 HTML을 만들고, SPA는 브라우저가 데이터를 조회해 화면을 갱신한다. 사용자 web은 공개 콘텐츠 SSR과 브라우저 상호작용을 함께 사용하고, adminweb은 SPA를 우선 검토한다.

## 2. 사용자와 서비스 영역

| 사용자 | 화면에서 할 일 | 제한 |
|---|---|---|
| Guest | 공개 게시글·프로젝트·블로그 탐색과 검색 | 작성·댓글·좋아요는 로그인 필요 |
| ACTIVE USER | 내 콘텐츠·프로필·Board 관리, 댓글·좋아요 | 콘텐츠 작성·수정·미디어는 프로필 완료 및 소유권 필요 |
| MANAGER | 콘텐츠 검수·차단·강제 삭제, 댓글·회원·분류 운영 | USER 콘텐츠 작성·댓글·좋아요 권한 없음 |
| MASTER | MANAGER 기능과 관리자 계정 운영 | 세부 계정 대상·동작 제한은 서버 계약을 따름 |

프로필 미완료는 모든 회원 동작을 차단하는 상태가 아니다. 댓글·좋아요·Board 관리의 조건은 각 API대로 적용한다. SUSPENDED·WITHDRAWAL_PENDING 처리 역시 서버가 최종 결정한다.

## 3. 사용자 web의 목표

1. 여러 개발자의 공개 Post와 Project를 각각 탐색·검색한다.
2. 특정 개발자의 handle 주소에서 공개 글·Board·프로젝트를 읽는다.
3. Post의 TEXT/CODE 블록, Project의 주요 기능·기술 태그·링크·미디어를 읽기 좋게 표시한다.
4. Naver 로그인 후 최초 프로필 설정과 내 콘텐츠 관리를 제공한다.
5. 공개·비공개 콘텐츠 작성·수정·삭제, 연결된 Board·Project와 미디어를 관리한다.
6. 댓글의 PUBLIC/SECRET 접근 범위와 좋아요 상태를 실제 응답으로 표시한다.
7. 표시 이름 변경 가능 시각, 탈퇴 예약·취소·재로그인을 안내한다.

개인 블로그와 전체 서비스 목록은 다른 범위다. 서비스 목록에 특정 회원의 블로그명·Board·통계를 전역 정보처럼 넣지 않는다. handle로 빈 블로그의 메타데이터를 얻는 계약과 개인 Project의 회원 ID 식별은 [결정 사항](DECISIONS.md)에서 미해결로 관리한다.

## 4. 관리자 adminweb의 목표

사용자 web과 독립적인 로그인·운영 탐색을 제공한다. 목록 필터, 대상 상세, 차단·해제·삭제 결과와 오류를 표시한다. MASTER 전용 계정 메뉴를 구분한다. [관리자 화면 명세](../adminweb/SCREEN_SPEC.md)를 따른다.

현재 관리자 저장소 경로·기술 스택·구현 상태는 확인되지 않았다. 이 요구사항은 현재 구현 목록이 아니다.

## 5. 범위 밖

MVP에는 대댓글·북마크·신고 처리·팀 협업·추천·자동 완성을 추가하지 않는다. 제공되지 않는 자기소개·연락처·월별 통계·계획 중 Project 상태를 시안 때문에 가짜로 채우지 않는다. 자동 저장·임시글 복구·오프라인 편집은 별도 계약과 요구가 생기기 전 구현 범위에 포함하지 않는다.

## 6. 화면 완료 조건

정상 데이터·로딩·빈 결과·입력 오류·연결 실패·권한 거부·미존재·저장 중·성공 상태가 있어야 한다. 모바일 및 키보드 동작을 확인한다. 실제 데이터·역할·입력·응답을 사용하고 mock 검증과 실제 API·OAuth 검증을 구분한다.

공개 페이지는 본문과 title·description·canonical을 일관되게 구성한다. SEO는 검색 순위를 보장한다는 의미가 아니다. 개인·관리자 데이터는 검색 노출 대상이 아니다.

## 7. 구현 순서 제안

공개 목록·상세 → 로그인·세션 복구·최초 설정 → 내 콘텐츠·Board·편집 → 댓글·좋아요·미디어 → 계정·탈퇴 순서로 한 기능의 조회·변경·오류·검증을 함께 완성한다. 관리자 기능은 별도 저장소의 준비 상태에 따라 독립적으로 진행한다. 디자인 확정이나 계약 보완이 필요한 기능은 [결정 사항](DECISIONS.md)에 기록한다.
