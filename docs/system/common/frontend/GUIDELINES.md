# 프론트엔드 공통 작업 기준

특정 프레임워크·렌더링 방식·서비스에 종속되지 않는 기준이다.

- 구현할 화면·사용자·입력·로딩·빈 상태·실패·완료 조건을 먼저 확인한다. 시안·예시 데이터를 실제 구현 완료나 제공되는 API로 간주하지 않는다.
- 라우트 조립, 기능별 화면·상태, API 호출, 공통 UI의 책임을 구분한다. 실제 필요가 생기기 전 모든 기능에 계층을 복제하지 않는다.
- 서버 데이터, 폼 입력, URL의 검색·필터, 일시적인 UI 상태를 구분한다. 같은 서버 데이터를 여러 store에 불필요하게 복제하지 않는다.
- 서버의 API·인증·인가 계약을 따른다. 화면에 버튼을 숨기는 것만으로 권한을 보장하지 않는다. 토큰 저장·갱신 방식은 프로젝트의 보안 계약을 따른다.
- 사용자별 데이터와 공개 데이터의 캐시를 구분한다. 계정 변경·로그아웃 뒤 다른 사용자 데이터가 남지 않도록 한다.
- 서버 비밀을 브라우저 번들·공개 환경변수·로그에 전달하지 않는다. 사용자 콘텐츠를 안전하게 렌더링한다.
- 로딩·빈 목록·입력 오류·연결 실패·권한 거부·처리 성공을 표현한다. 실패를 예시 콘텐츠로 숨기지 않는다.
- 키보드 탐색·label·focus·대체 텍스트와 모바일 표시를 확인한다.
- 프레임워크와 패키지 버전은 설치된 코드와 공식 문서에서 확인한다. SSR·SPA 여부는 화면 목적과 배포 환경에 맞춰 결정한다.
- 존재하는 package scripts를 확인한 뒤 변경에 맞는 타입 검사·테스트·빌드를 실행한다. 없는 테스트 명령이나 미실행 검증을 성공했다고 보고하지 않는다.
- 모의 API, 실제 API 연결, 실제 인증, 브라우저 및 시각 검증의 결과를 구분한다.
